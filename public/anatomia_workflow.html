ANATOMÍA DE UN WORKFLOW

Qué lo inicia, cómo pasan los datos entre sus pasos, para qué sirven las decisiones y los controles, y qué resultado produce.

DESLIZA PARA EXPLORAR

01 · Vista general

¿Qué es un workflow?

Un proceso definido mediante pasos conectados: tiene un inicio, acciones, decisiones y un resultado.

1Disparador→2Pasos con datos→3Decisiones y controles→4Resultado

Como la estructura está definida, se puede repetir cada vez que llega un caso nuevo.

Ejemplo de todo el recorrido: llega una solicitud, se registran sus datos, se comprueba si está completa y se resuelve.

  1. 01Llega una solicitud
  2. 02Registrar datos
  3. 03Comprobar información
  4. 04¿Está completa?
  5. 05Enviar al responsable
  6. 06Solicitar completarla
  7. 07Registrar el resultado

02 · Disparador

El disparador inicia el proceso

Algo ocurre y el workflow arranca. En el ejemplo: llega una solicitud.

La señal entra por el inicio y activa la primera estación.

Un disparador puede ser un formulario enviado, un correo, una hora programada o una persona que lo inicia a mano. Sin disparador, el proceso espera.

03 · Pasos con datos

Cada paso recibe algo y entrega algo

  1. 02Registrar datos

    Recibe
    La solicitud tal como llegó.
    Entrega
    Una ficha con tres campos: asunto, detalle y adjunto.

  2. 03Comprobar información

    Recibe
    La ficha.
    Entrega
    La misma ficha con un estado: completa o incompleta.

La salida de un paso es la entrada del siguiente.

04 · Decisiones

Una decisión elige el camino

La condición: ¿la información está completa?

SÍ → enviar al responsable NO → solicitar que se complete

Esta solicitud está completa: se envía al responsable.

La regla se define antes. Así, dos solicitudes que cumplen la misma condición siguen el mismo camino.

05 · Controles

Un control no deja pasar datos incompletos

Llega otra solicitud. Al comprobarla, falta el adjunto.

La decisión la manda por el camino NO: no se envía al responsable.

EN PAUSA · SE SOLICITA COMPLETAR

El proceso no sigue como si todo estuviera bien: se detiene y pide lo que falta. Cuando llega, la solicitud vuelve a entrar por el inicio.

Un control también puede ser la revisión de una persona antes de continuar.

06 · Resultado

El resultado queda registrado

Cada solicitud termina con una salida clara: enviada o en espera de información.

  • El disparador inicia el proceso: llegó una solicitud.
  • Los pasos reciben datos y entregan datos: solicitud → ficha → ficha con estado.
  • La decisión elige el camino según una condición: ¿está completa?
  • El control detiene el avance y pide lo que falta.
  • El resultado queda registrado, y el proceso está listo para la siguiente solicitud.

UN WORKFLOW NO ES UNA HERRAMIENTA.
ES UN PROCESO QUE SE PUEDE REPETIR.

La herramienta cambia cómo se representa el proceso y quién ejecuta cada paso.

La estructura se mantiene: disparador → pasos con datos → decisiones y controles → resultado.
